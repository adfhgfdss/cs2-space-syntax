## 2026-09-19 深夜：实验一（构形敏感性）+ 实验二（可理解度）做完了

两个实验都按要求用 **depthmapX**（官方命令行版 `tools\depthmapXcli.exe`）计算轴线指标，
报告与文件清单见 **[实验报告_构形敏感性与可理解度.md](实验报告_构形敏感性与可理解度.md)**。

* **实验一**：构形指标 × 交火热点（20 场职业赛的 3,255 次击杀）。
  相关方向为正但弱：Dust2 整合度 ρ=+0.089 / 选择度 ρ=+0.308；
  Mirage 整合度 ρ=+0.276。整合度前后 20% 的交火密度比：Dust2 1.21×、Mirage 4.08×。
  → **"打起来的地方"和"常走的地方"不是同一件事**；选择度比整合度更能解释交火。
* **实验二**：可理解度 R²（连通度 × 全局整合度）。**两种口径都显示 Mirage 更高**
  （轴线图 0.104 vs 0.028，VGA 0.881 vs 0.432），与"Dust2 三路结构 → R² 更高"的
  预期相反。原因推测：Dust2 的长通道局部连通度低但全局整合（局部与全局脱钩），
  而 Mirage 的环形结构让局部线索更能预测全局位置。

**为什么轴线图是自动生成的**：depthmapX 需要输入画好的轴线（它把输入线直接当轴线），
而这台机器上没有人工描图的条件。所以我用"导航网格 → 骨架化 → 折线简化 → 端点吸附"
自动生成轴线（Dust2 159 条 / Mirage 178 条），**分析引擎仍是 depthmapX 本体**。
这一步的后果与局限写在实验报告第 3 节。

| | de_dust2（10 场） | de_mirage（10 场） |
|---|---|---|

  相关（+0.396 / +0.346）；而**击杀位置**偏向视觉开阔处（连通度 +0.287）。
* **稳健性检查通过**：平台局样本给出几乎相同的模式（dust2 0.41，Mirage 开局

## 七、踩过的坑（我已经绕开了，但你改代码时要注意）

1. **awpy 2.0.2 的 `Demo.parse()` 在当前 CS2 demo 上会崩**：`round_end.winner`
   现在是整数，awpy 仍调用字符串方法。所以管道直接驱动底层 demoparser2。
2. **demoparser2 返回 pandas，不是 polars**，且事件坐标必须显式请求
   （`player=["X","Y","Z"]`），否则没有位置列。
3. **受害者坐标是 `user_X/Y/Z`**，不是 `victim_X/Y`。
4. **`player_death` 没有 `side` 字段**，只有 `team_num`（2=T，3=CT），需自己派生。
5. **`parse_events` 返回 `[(事件名, DataFrame), ...]` 列表**，不是字典。
6. **Y 轴是反的**：`radar_y = (pos_y - world_y) / scale`。
7. **换 demo 后必须先跑 `extract_events.py`**，否则 `analyse_map.py` 会拿旧数据
   画新地图。
