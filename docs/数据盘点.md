# 数据盘点：de_dust2 / de_mirage 双图对比研究

## 零、采样设计（2026-09-19 晚更新）

**研究样本 = HLTV 职业赛 demo，每图 10 场。** 由 `fetch_pro_demos.py` 自动抓取
（候选来自 `hltv.org/results?content=demo`，只取比赛地图里含 Dust2 / Mirage 的场次，
一场比赛一个压缩包、里面含该场所有地图的 dem）。

| 用途 | 数据 | 位置 |
|---|---|---|
| **研究样本** | HLTV 职业赛，每图 10 场 | `demos\<地图>\` |
| 预实验 / 稳健性检查 | 完美平台对局 7 场 + 公开测试录像 1 场 | `demos_pug\<地图>\` |
| 几何层 | 与样本无关，两图已完成 | `out\<地图>_syntax_*` |

样本清单（含每场的对阵、赛事、回合数、SHA256）会写在 `demos\manifest.json`
与 `out\behaviour\<地图>_meta.json`，报告的数据一节直接引用。

> 为什么换成职业赛：预实验用的是平台路人局，运动逻辑受"上分习惯"影响更大；
> 职业赛的战术纪律更强、样本同质，适合做地图间对照（也与 [G4] 的职业赛口径一致）。
> 平台样本不作废——它会作为"不同水平的玩家群体是否给出同样结论"的稳健性检查。

## 三、还缺什么（按优先级）

1. **继续各图扩样**（4 → 10–20 场）：现在的结论在地图层面已经稳定
   （Mirage 的结果从 1 场到 4 场没变、dust2 上出现了明确的正相关），但
   **统计推断**还需要更多场次；完美平台上那 14 个中断下载补完，可再加约 45 回合。
2. **统一数据来源**：现在 7 场来自完美平台、1 场来自路人匹配。虽然分析显示
   结论不依赖于那 1 场（Mirage 从 1 场到 4 场结果一致），但报告里要明确写出
   这个混合；若能补齐为清一色平台对局（或清一色职业赛）更干净。
3. **（可选）职业比赛对照**：如果希望在讨论里直接对话 [G4]（职业比赛的地图
   架构与竞技平衡），需要另下一批职业赛 demo——获取方式见
   `数据获取.md` 路径 3。

具体获取步骤、放置规范、命名建议写在 `数据获取.md`。

## 四、数据怎么放、命令怎么跑

```
demos\                        ← demo 放这里，平铺或按地图分目录都可以
  de_dust2\
    20260919_mm_01.dem
    20260919_mm_02.dem
  de_mirage\
    20260918_mm_01.dem
out\
  behaviour\                  ← ingest_demos.py 按地图分好的行为数据
    de_dust2_tracks.parquet
    de_dust2_meta.json
    de_mirage_tracks.parquet
    ...
```

```powershell
# 1) 吃 demo（自动按地图分组；几场都行）
.venv\Scripts\python.exe ingest_demos.py --demos demos

# 2) 两图几何层 + 有 demo 的图像的行为层 + 对比，一条命令
.venv\Scripts\python.exe run_all.py de_dust2 de_mirage --demos demos --compare

# 3) 随时重新盘点数据体量
.venv\Scripts\python.exe data_inventory.py
```

新增 demo 后**不用改任何代码**：`ingest_demos.py` 会重新分组，
`analyse_behaviour.py` 会在报告里写明用的是几场 demo、多少回合。

## 五、扩样后要盯住的两件事

1. **样本量可比**：两图场次/回合数尽量接近，否则跨图差异无法归因于地图。
2. **口径可比**：格子边长（16 px）在两图的**实际游戏单位**不同（70.4 vs 80.0），
   这是雷达图 `scale` 不同造成的（4.4 vs 5.0）。跨图比较时要么接受这个差异
   并在报告里说明，要么改用"世界单位"定义栅格（例如统一按 70 游戏单位切格）。
   这一条我可以在扩样后按你的偏好统一处理。
